# Rickhouse — Design Brief

## 01 — The Core Idea

**Rickhouse is an eccentric field guide to an obsessive spirits collection.**

It is a Swiss-designed system for cataloging, understanding, and remembering a liquor collection—but one that has clearly been lived in.

The underlying system is precise:

* rigorous grids
* strong typography
* dense information
* accurate data
* predictable interaction
* excellent search and filtering
* clear hierarchy

The surface is human:

* bright category color
* real bottle photography
* painter's tape
* Sharpie annotations
* occasional hand-drawn illustrations
* physical-looking interventions
* personal stories
* contextual humor
* Rick, the dog, appearing when he has something to say

### The fundamental tension

**Precision underneath. Humanity on top.**

Rickhouse should feel like someone extremely organized has been collecting things obsessively for years—and occasionally scribbles something ridiculous in the margin.

---

# 02 — Design Philosophy

### Curiosity over connoisseurship

Rickhouse should never feel like a luxury spirits publication, private club, or expert-only database.

It celebrates obsession and curiosity rather than expertise.

The user should feel invited to investigate their own collection.

### Take the collection seriously. Don't take yourself seriously.

The data is real. The stories are real. The collection matters.

The interface can still say:

> "WHY DO YOU OWN SIXTEEN BOTTLES OF MEZCAL?"

Humor should come from the collection itself.

**The data earns the joke.**

### Swiss design that has been lived in

The visual foundation is Swiss modernism:

* Helvetica Now
* rigorous grids
* strong alignment
* clear hierarchy
* information density
* restrained structural elements

But it has accumulated personality over time.

It is not pristine Swiss design.

It is **Swiss design that has been lived in.**

---

# 03 — Emotional Hierarchy

Rickhouse should produce these reactions in roughly this order:

### 1. "Oh shit, this is fun."

Immediate visual character.

### 2. "Holy shit, look at my collection."

The user's actual bottles are the stars.

### 3. "Whoa, I can actually see what's going on."

The system reveals patterns and useful information.

The experience should move naturally from:

**Fun → Discovery → Data**

without sacrificing utility.

---

# 04 — Visual Identity

## Typography

### Primary typeface

**Helvetica Now**

This is the workhorse.

Use it for:

* navigation
* tables
* labels
* metadata
* numbers
* controls
* forms
* headings
* system UI

Typography should feel Swiss, confident, and highly legible.

### Secondary typography

A serif may appear occasionally for:

* stories
* editorial passages
* tasting narratives
* special moments

Display typography should be rare.

Do not introduce quirky fonts simply to create personality.

### Principle

**The typography provides the discipline. The physical interventions provide the humanity.**

---

# 05 — Color

Rickhouse is **colorful by default, restrained by structure.**

The collection owns the color system.

Category colors should feel like:

* painter's tape
* ink
* bottle labels
* packaging
* physical materials

They should NOT feel like generic SaaS status colors.

### Suggested category families

* Agave → pink / coral
* Whiskey → orange / yellow
* Gin → green
* Rum → red
* Vodka → blue
* Liqueurs → purple

Exact colors can evolve.

### Color has a job

Use color to:

1. identify spirit category
2. highlight something important
3. create visual rhythm
4. make something funny or weird
5. celebrate something

Do not add color merely because an empty space exists.

### Avoid

* generic blue/purple SaaS palettes
* gradients
* excessive rainbow effects
* color without semantic purpose

---

# 06 — Surfaces

The base world is **slightly off-white with multiple paper tones**.

Think:

* ivory
* cream
* pale gray
* slightly yellowed paper
* occasional brighter white

This is variation in tone—not fake parchment texture.

Avoid literal skeuomorphic paper backgrounds.

Dark mode is a deliberate alternate world:

**Rickhouse after sunset.**

It should not simply invert the light theme.

The Swiss structure and category colors remain intact.

---

# 07 — Grid & Layout

### Core rule

> **The grid is the rule. Breaking the grid is the reward.**

Most interfaces should have:

* strong alignment
* predictable columns
* clear spacing
* deliberate density

But meaningful moments can:

* span unusual widths
* overlap
* break alignment
* expand dramatically
* introduce physical interventions

Random asymmetry is not personality.

Every visual rebellion should have a reason.

---

# 08 — Physicality

Physical elements are contextual, not universal decoration.

Possible interventions:

* painter's tape
* black Sharpie handwriting
* crooked labels
* stamps
* scribbles
* overlaps
* paper edges
* folds
* hand-drawn marks

### Painter's tape

Painter's tape is a recurring visual device.

It can communicate:

* category
* OPEN
* BACK BAR
* GIFT
* special status
* jokes
* annotations

But tape should never become wallpaper.

### Principle

**The underlying system is disciplined. The surface can get messy.**

---

# 09 — Cards & Containers

Do NOT default to rounded cards.

Avoid:

* card soup
* floating containers everywhere
* excessive corner radius
* unnecessary shadows
* excessive whitespace

Containers should exist because they communicate structure.

Hierarchy should often come from:

* typography
* spacing
* rules
* alignment
* color
* imagery

rather than a box around everything.

---

# 10 — Photography

Real bottle photography is one of Rickhouse's most important differentiators.

### Two-photo philosophy

Every bottle can have:

**Identity Photo**

* clean
* recognizable
* consistent
* catalog-oriented

**Life Photos**

* bars
* trips
* dinners
* shelves
* receipts
* gifts
* people
* label details
* imperfect personal moments

### Principle

> **Catalog photography tells you what it is. Life photography tells you what happened.**

Catalog photography should remain disciplined.

Life photography can become:

* editorial
* physical
* messy
* overlapping
* taped
* cropped
* contextual

Do not artificially make every photo look beautiful.

A terrible photo can be an important memory.

---

# 11 — Rick

Rick is the white Aussiepoo who acts as Rickhouse's recurring character.

He is **not a permanent mascot.**

### Rick has two visual modes

**Canonical Rick**

* polished illustration
* strong silhouette
* simple geometric construction
* black ink / Sharpie influence
* occasional flat category color
* expressive and charming

**Doodle Rick**

* rough margin drawings
* imperfect
* casual
* looks like someone has been drawing their dog in the margins for years

### Influences

* Field Notes
* Swiss graphic design
* children's-book illustration

Avoid:

* Pixar-style mascot design
* generic SaaS mascots
* hyper-polished character branding

### Rick's role

> **Rick lives here. He doesn't work here.**

He should appear:

* in margins
* in empty states
* in milestones
* in discoveries
* in contextual jokes
* in loading moments
* in meaningful interactions

He should NOT appear:

* in permanent navigation
* on every card
* in every empty corner
* as a mandatory UI element

If users start noticing Rick because he's everywhere, there is too much Rick.

---

# 12 — Voice

Rickhouse is primarily:

**A smart friend who gives you shit.**

Secondary influences:

* dry/deadpan
* bartender
* eccentric archivist
* occasionally drunk

### Voice principle

> **Rickhouse knows when to shut up.**

Quiet during:

* data entry
* editing
* filtering
* repetitive work
* serious errors

More conversational during:

* Home
* bottle stories
* discoveries
* milestones
* unusual statistics

### Profanity

Normally casual.

When the data genuinely warrants it, Rickhouse can escalate.

Example:

> You have 14 bottles of bourbon.

Then:

> You already have 14 bottles of bourbon.

Then:

> Zach, what the fuck.

Do not use profanity merely to appear edgy.

---

# 13 — Proactive Intelligence

Rickhouse should actively notice patterns.

It should look for:

* purchasing patterns
* category shifts
* favorite distilleries
* spending changes
* unopened bottles
* aging bottles
* duplicates
* near-duplicates
* unusual proof/age patterns
* geographic concentrations
* tasting-note patterns
* anniversaries
* milestones
* statistical outliers

### Personality levels

* Quiet
* Observant
* **Nosy** — default
* Unhinged

The user can reduce the personality level.

### Principle

> **Rickhouse pays attention. You decide how much it talks.**

Observations must be based on actual collection data.

Never manufacture personality without evidence.

---

# 14 — Navigation

Primary navigation:

**Home · Collection · Labels · Groups · Numbers · Settings**

Navigation is:

**Swiss foundation + physical interventions.**

Global navigation should remain:

* predictable
* stable
* clean
* strongly typographic
* grid-aligned

Personality may appear through:

* tape
* category color
* annotations
* contextual marks
* subtle physical motion

Never sacrifice orientation for personality.

---

# 15 — Information Architecture

## Labels

Labels are the **reference library**.

A Label is the canonical product/reference record.

Example:

**Weller 107**

contains:

* standardized bottle photography
* producer
* category
* country
* proof
* age
* mash bill / ingredients
* history
* variations
* related labels
* ownership count

> **Labels are knowledge. Collection is ownership.**

## Collection

Collection contains physical bottles.

A Label can have multiple physical bottles.

Example:

**Weller 107**

* Bottle #1
* Store Pick ABC
* Private Selection Barrel #1234
* Bottle #4

> **The Labels are the species. Bottles are the specimens.**

## Groups

Groups are personal, curated collections.

Examples:

* Japan 2026
* Store Picks
* Mara's Bottles
* Bought Under $50
* Things I Want to Drink Soon
* Why Did I Buy This?

Groups are not merely saved filters.

> **The database tells you what you own. Groups tell you what it means.**

---

# 16 — Collection

Collection defaults to **Table View**.

The table is:

* dense
* sortable
* filterable
* editable
* keyboard-friendly
* highly scannable

Example:

`[thumbnail] Name | Category | Distillery | Proof | Age | Purchase Price | Opened | …`

Bottle thumbnails should be small but recognizable.

Hovering can enlarge the preview.

Missing photos should have an intentional placeholder.

### Table personality

Default treatment:

**Clean Swiss table + physical accents**

Possible interventions:

* category color
* tiny tape marks
* handwritten notes
* small Rick doodles
* contextual annotations
* bottle relationship indicators

But the table must remain a workbench.

> **The workbench stays a workbench.**

---

# 17 — Gallery

Gallery is where the collection becomes physical.

> **Table = perfect organization.
> Gallery = curated accumulation.**

Normal bottles:

* consistent scale
* rhythm
* grid
* occasional overlap

Related bottles:

* cluster
* stack
* stagger
* family grouping

If four bottles belong to the same Label, the Gallery can present them as a family.

> **The database sees four bottles. The gallery sees a family.**

The more meaningful the relationship between objects, the more physical the arrangement can become.

---

# 18 — Bottle Detail

Every bottle shares a common factual foundation.

But its presentation can change depending on its story.

Bottle Detail can include:

* acquisition
* price
* location
* people
* places
* experiences
* tasting history
* notes
* photographs
* media
* opening
* fill level
* ownership history

> **The bottle isn't just an inventory record. It's an object with a story.**

Rickhouse catalogs **the life of a bottle**, not just the bottle itself.

---

# 19 — Bottle Lifecycle

Core states:

**Unopened → Open → Almost Gone → Empty**

Additional lifecycle states may include:

* Gifted
* Sold
* Lost / Misplaced

### Important

**Empty does not mean deleted.**

A bottle can leave the physical collection while remaining in Rickhouse's history.

Fill level should be visual rather than pretending to know exact ounces:

* Full
* ¾
* ½
* ¼
* Almost Gone
* Empty

### Opening

Opening can trigger a meaningful visual moment.

But the Collection table must always make state obvious.

> **State should be obvious. Celebration should be contextual.**

---

# 20 — Add Bottle

Add Bottle is:

> **A great data-entry form wearing a little costume.**

It must remain:

* fast
* keyboard-friendly
* efficient
* excellent at routine data entry

After saving, personality can appear:

* “New bottle acquired.”
* category color appears
* painter's tape label
* collection count ticks upward
* bottle photo enters the collection
* Rick reacts

Personality never slows entry.

---

# 21 — Groups

Groups are scrapbook-like curated collections.

A Group may contain:

* cover image
* handwritten description
* bottle clusters
* personal photographs
* painter's tape
* annotations
* Rick doodles
* dates
* locations
* relationships between bottles

Different Groups can have different visual identities.

Still, every bottle remains a real data record.

> **Groups = stories.**

---

# 22 — Numbers

Numbers begins with curiosity rather than dashboards.

Examples:

> YOUR MOST EXPENSIVE BOTTLE

> YOU HAVE 17 BOTTLES FROM KENTUCKY

> MOST OF YOUR COLLECTION IS 90–110 PROOF

> YOU HAVE 6 BOTTLES YOU'VE OWNED FOR 5+ YEARS

Clicking an observation should reveal:

**Huh, that's interesting.**
→ **Why?**
→ **Show me the data.**
→ **Let me investigate.**

Numbers should eventually provide deep analytical tools, but discovery comes first.

---

# 23 — Data Visualization

> **The numbers are rigorous. The presentation can have personality.**

Charts should be:

* accurate
* readable
* Swiss/grid-based
* dense enough to investigate
* category-colored

Then, when warranted:

* handwritten annotations
* tape callouts
* visual observations
* Rick reactions
* unusual markers

The joke comes **after** the data.

Never distort a chart to make it entertaining.

---

# 24 — Timeline

Timeline is a first-class experience.

It can combine:

* acquisition
* discovery
* trips
* gifts
* tastings
* photos
* memories
* openings
* notes
* major collection events

It exists globally and within individual bottles/Groups.

> **Rickhouse doesn't just show what you own. It shows how the collection happened.**

---

# 25 — Physical Locations

Model the physical world now so it can be visualized later.

Useful defaults:

* Home Bar
* Kitchen
* Storage
* Off-site

But support custom/nested locations eventually:

`Home → Bar → Shelf 2 → Left Side`

The initial UI can remain simple.

> **Model the physical world now. Visualize it later.**

---

# 26 — Search & Filtering

Search should be:

**Powerful but approachable.**

Provide:

* instant forgiving search
* combined filters
* obvious sorting
* common filters one click away
* complex combinations without query syntax
* clear active-filter state
* easy exit/reset

> **Simple to ask. Powerful when you care.**

Never make Rickhouse feel like database software.

---

# 27 — Home

Home is a **living field notebook**.

It is not:

* KPI card soup
* a dashboard
* a static cabinet
* a marketing landing page

It should contain a constantly changing mix of:

* collection observations
* bottles
* photos
* statistics
* notes
* discoveries
* milestones
* Rick interventions

The underlying layout uses a strong grid.

Interesting content can break out of it.

> **The grid is the notebook. The interesting stuff gets to spill into the margins.**

Home should make the user think:

> “Oh shit, this is fun.”

---

# 28 — Mobile

Mobile is a **field companion**, not a shrunken desktop application.

### Desktop

The workbench:

* collection management
* bulk editing
* analytics
* Groups
* Timeline
* configuration
* deep investigation

### Mobile

The field:

* look up a bottle
* check whether something is already owned
* add a bottle
* photograph a bottle
* record a tasting
* add a story
* add photos
* update location
* update fill level

> **Desktop = study the collection.
> Mobile = live with the collection.**

Future versions may expand mobile into a richer experience, but V1 should prioritize these field use cases.

---

# 29 — Responsive Design

Do not simply shrink desktop layouts.

Use:

* fluid behavior where appropriate
* deliberate breakpoints
* contextual adaptations
* progressive disclosure

Major experiences can recompose substantially between desktop and mobile.

A rich Bottle Detail can remain visually rich.

A dense Collection table can become a focused mobile browsing experience.

---

# 30 — Forms

Routine forms should be quiet and efficient.

Special forms can become expressive.

### Routine

* Edit bottle
* Update metadata
* Filtering
* Configuration

### Expressive

* Add Bottle
* Tasting
* Create Group
* Open Bottle
* Import Collection

> **The more often I use it, the less it gets in my way.**

---

# 31 — Iconography

> **Function is Swiss. Meaning can be weird.**

Functional icons should be:

* clean
* geometric
* consistent
* immediately understandable

Use custom illustration/marks when the concept warrants it.

Do not turn every button into an illustration.

### Distinction

**Icon = tells you what a control does.**

**Illustration/mark = tells you something about the world you're in.**

---

# 32 — Motion

Motion hierarchy:

### 1. Satisfying

* dragging
* sorting
* snapping
* natural number changes
* chart growth
* reordering

### 2. Playful

* bottle wobble
* tape movement
* Rick reactions
* milestone celebrations
* ridiculous data interruptions

### 3. Exploratory

* hidden information
* interactive statistics
* bottle relationships
* Easter eggs

Motion must communicate or delight.

Never animate something simply because modern applications animate things.

---

# 33 — Sound

Sound is optional personality.

Settings:

* Sound Effects On/Off
* Volume

No music or persistent audio.

Possible sounds:

* soft clicks
* paper/tape sounds
* satisfying save
* bottle/clink
* milestone sound
* rare 2319 sound

> **Sound is seasoning, never information.**

Rickhouse should have personality without demanding attention.

---

# 34 — Loading

> **Make waiting feel like something is happening—not like the app is broken.**

Fast operations should feel instant.

Short waits can use:

* sorting
* filing
* snapping
* subtle physical movement

Meaningful waits may involve Rick.

Long waits need clear status/progress.

Never use an endless cute animation to hide a slow system.

---

# 35 — Empty States

Empty states combine:

**Characterful copy + visual gag.**

Examples:

* Empty collection → Rick looks confused.
* Empty Group → unfinished scrapbook page.
* No tasting notes → blank notebook page.
* No search results → Rick investigating with a magnifying glass.

The visual joke must never obscure the action.

> **Visual gag + personality, then utility.**

---

# 36 — Errors

> **Tell me what went wrong. Then make me smile.**

Every error should communicate:

1. What happened
2. Whether anything was saved
3. What the user can do

Then personality can appear.

Harmless failures can have jokes.

Serious data failures should prioritize clarity and recovery.

### Core rule

**Clarity is mandatory. Personality is optional.**

---

# 37 — Destructive Actions

> **Don't make me confirm everything. Make consequential things feel consequential.**

Reversible actions:

**Do it + offer Undo.**

Meaningfully destructive actions:

**Confirm clearly.**

Irreversible actions:

**Stronger confirmation + contextual personality when appropriate.**

Do not obscure consequences with jokes.

Because bottle history matters, distinguish between:

* removing ownership
* changing lifecycle state
* deleting a record
* deleting historical memories

A bottle leaving the collection should not necessarily disappear from history.

---

# 38 — Notifications & Toasts

Notifications can be characterful.

Possible ingredients:

* tape labels
* physical motion
* Rick reactions
* sound
* short contextual copy

But they must remain:

* brief
* readable
* non-blocking

Example:

> **BOTTLE SAVED**
> Rick has filed the evidence.

Personality should enhance confirmation rather than turn it into an interruption.

---

# 39 — Onboarding

> **Show, don't explain.**

The first experience should:

1. briefly introduce Rickhouse
2. establish the visual world
3. show the collection experience
4. immediately invite the user to do something

Prefer contextual teaching over tutorials.

For example:

> “This is a Label. Think of it as the thing on the shelf.”

Then later:

> “You own three of these. Those are bottles.”

Rickhouse should become understandable through use.

---

# 40 — Accessibility

Accessibility is part of the design system.

Personality must not depend on:

* seeing color
* reading handwriting
* perceiving motion
* hearing sound
* using a mouse
* perfect vision

Therefore:

* Color always has another indicator.
* Handwritten elements have readable equivalents.
* Motion respects reduced-motion settings.
* Sound is optional.
* Keyboard navigation is first-class.
* Screen-reader semantics are meaningful.
* Contrast remains sufficient.
* Physical interventions never obscure important information.

> **Accessibility doesn't remove the weirdness. It translates it.**

Provide strong accessibility options from the beginning, with room for additional preferences later.

---

# 41 — Personalization

V1 should have a strong point of view.

Start with a small set of curated choices:

* Light / Dark
* Personality intensity
* Sound
* Reduced motion
* accessibility preferences
* sensible density options

Later, introduce deeper customization:

* curated visual themes
* category palette variations
* additional density controls
* physicality levels
* potentially additional typography/display options

Do not build a “design your own dashboard” system.

> **Rickhouse has a point of view. You can adjust the volume.**

---

# 42 — Brand

> **Rickhouse has a mark. Rick has a face.**

The primary brand should use:

* strong Swiss/Helvetica Now wordmark
* understated field-guide / archival mark
* distinctive physical stamp/device

Rick can appear alongside the brand and become a secondary signature.

Rick can be part of:

* launch
* onboarding
* merchandise
* special editions
* loading moments
* major brand moments

But he should not turn every part of the product into “Rick's Liquor App.”

**Rickhouse = the world.
Rick = the character who lives in it.**

---

# 43 — Absolute Anti-Patterns

These should be treated as explicit design constraints.

### Never:

* rounded cards everywhere
* card soup
* excessive whitespace
* generic SaaS blue/purple
* gratuitous gradients
* glassmorphism
* random asymmetry
* quirky fonts everywhere
* generic mascot behavior
* Rick shoved into everything
* fake scrapbook chaos
* luxury spirits / private-club aesthetic
* faux-premium visual language
* KPI/dashboard-card soup
* animation for animation's sake
* personality that slows routine work
* jokes that obscure information
* fake data-driven observations
* museum/connoisseur elitism
* sterile all-digital aesthetic

### Especially avoid:

**“AI-generated app” syndrome.**

If a design decision feels like the obvious output of a modern UI generator, question it.

---

# 44 — The Five Most Important Rules

If implementation details ever conflict with this document, prioritize these:

### 1. Precision underneath. Humanity on top.

The system must work first.

### 2. The data earns the joke.

Personality should emerge from actual collection context.

### 3. The grid is the rule. Breaking the grid is the reward.

Don't create chaos for aesthetics.

### 4. Utility is never sacrificed for personality.

Rickhouse is a serious collection tool wearing a fun outfit.

### 5. Curiosity over connoisseurship.

The app should make the user want to investigate their own collection.

---

# 45 — The Rickhouse Test

Before shipping a significant visual component, ask:

**Does it feel collected rather than generated?**

**Does it make the actual collection more interesting?**

**Is the underlying information still immediately usable?**

**Is the personality contextual?**

**Does the weirdness have a reason?**

**Could this component exist in any generic SaaS app?**

If the last answer is yes, reconsider it.

---

# Final Identity

Rickhouse should feel like:

**A Swiss-designed field guide to an eccentric liquor collection.**

Helvetica Now and rigorous grids provide the structure.

Bright color, real bottle photography, painter's tape, Sharpie annotations, and occasional hand-drawn illustrations make it feel collected rather than manufactured.

The interface is playful and occasionally absurd, but the weirdness is contextual.

**The data earns the joke.**

**Precision underneath. Humanity on top.**

**Curiosity over connoisseurship.**

**Swiss design that has been lived in.**
